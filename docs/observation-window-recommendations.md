# Observation window recommendation engine (Issue #19)

This is a deterministic, offline interval search for AstroManager v0.3.0.
It reuses the astronomical darkness, target visibility, lunar ephemeris,
normalized weather forecasts, and explainable interval scoring implemented
in Issues #11–#18. It does not fetch weather, persist data, or invoke Riverpod.

## Files

- `lib/features/intelligence/domain/models/observation_window.dart`
- `lib/features/intelligence/domain/services/observation_window_recommendation.dart`
- `test/features/intelligence/observation_window_recommendation_test.dart`

## Public entry points

- `ObservationWindowRecommendation.forObservingNight(...)`: uses the observing
  location's IANA timezone and the local noon-to-noon night generated by
  `SolarEvents.calculateForLocalDate`. Handles DST changes automatically.
- `ObservationWindowRecommendation.forUtcPeriod(...)`: accepts any explicit UTC
  period up to 48 elapsed hours; it computes -18° solar crossings on the fly.

Both accept multiple catalog targets, an explicit `evaluatedAtUtc` instant, an
optional `WeatherForecastSnapshot`, optional optical metrics, a scoring profile
and `ObservationWindowOptions`.

## Algorithm

1. Find astronomical darkness (geometric solar center strictly below -18°).
2. For each target, intersect darkness with altitude visibility from
   `TargetVisibility.calculate`, using the configured minimum altitude.
3. Generate candidate windows within each continuous intersection. Try
   durations from `minimumSessionDuration` to `maximumSessionDuration` in
   increments of `candidateStep`; include the exact upper duration even if
   it falls between increments. Try grid-aligned start times and the latest
   valid start for each duration.
4. Score each candidate with
   `AstrophotographySuitabilityScoring.score`. This accounts for altitude,
   usable duration, darkness, lunar conditions, weather and optical framing.
5. Independently determine weather coverage over all overlapping whole UTC
   forecast hours. An hour missing entirely contributes zero time coverage;
   an hour containing missing or unsupported parameters lowers parameter
   coverage. Forecast location mismatch and stale data are never treated
   as valid forecast coverage.
6. Rank by score descending, then non-provisional over provisional, longer
   duration, earlier UTC start, and target ID. Suppress near-duplicate windows
   for the same target only, using overlap as a fraction of the shorter window.

The highest ranked window has the best score **among evaluated candidates**,
not a mathematically proven continuous-time optimum. To increase temporal
resolution, reduce `candidateStep` (with an associated compute cost).

The maximum altitude time is found on the scoring profile's sample grid; it
is an approximation and should not be confused with exact culmination.

## Incomplete forecasts

`ObservationWindow.weatherStatus` is one of:

- `complete`: full interval and all ten scored weather parameters available
- `partial`: forecast is fresh but some hours/parameters are missing
- `missing`: no forecast, invalid location, or no usable forecast hours
- `stale`: forecast exceeded cache freshness limits or is a stale fallback

`weatherTimeCoverage` and `weatherParameterCoverage` are fractions in [0, 1].
`isProvisional` is true for partial/stale/missing weather or other incomplete
scoring inputs. `score.factors` exposes all six raw scores, weights and textual
explanations. The Issue #18 scorer caps the score at 50 when no trustworthy
weather is available. **Missing data never implies clear skies.** The source
forecast's issue/fetch timestamps remain untouched.

## Time and accuracy

All returned boundaries and ranking tie-breaks use absolute UTC instants.
Local-time handling occurs only while selecting the local observing night.
The custom-period darkness search samples the Sun every five minutes and
refines detected crossings to approximately one second; short events that
occur entirely between samples can be missed. Visibility boundaries follow
the existing `TargetVisibility` one-second bisection and sample resolution.
Geometric altitudes exclude local terrain masks and atmospheric refraction.
Lunar and weather scoring remain heuristics, not guarantees of photo quality.

For large catalogs, pass a shortlist from discovery rather than every OpenNGC
object in a synchronous UI build; the service evaluates candidates for each
supplied target. No network or storage calls are performed.

## Example

```dart
final recommendations = ObservationWindowRecommendation.forObservingNight(
  targets: selectedCatalogTargets,
  location: selectedObservingLocation,
  localDate: DateTime.utc(2026, 11, 1),
  evaluatedAtUtc: DateTime.utc(2026, 11, 1, 17),
  weather: weatherSnapshot,
  optics: selectedOpticalMetrics,
  options: const ObservationWindowOptions(
    minimumSessionDuration: Duration(hours: 2),
    maximumSessionDuration: Duration(hours: 4),
    candidateStep: Duration(minutes: 30),
  ),
);

for (final window in recommendations.rankedWindows) {
  print('${window.targetDesignation}: ${window.startUtc} – ${window.endUtc}');
  print('Score: ${window.score.score.toStringAsFixed(1)}');
  print('Weather: ${window.weatherStatus.name}');
  for (final factor in window.score.factors.values) {
    print('${factor.factor.name}: ${factor.explanation}');
  }
}
```
